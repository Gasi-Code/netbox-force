## 1. Що робить плагін

NetBox фіксує, *що* змінилося. NetBox Force вирішує, *чи зміна взагалі
допустима*, і може завчасно вимагати обґрунтування.

Він стоїть між кожною операцією збереження чи видалення та базою даних. Перш ніж
зміну буде записано, він може перевірити:

- чи вказано коментар до журналу і чи достатньо він довгий
- чи коментар не складається лише з порожніх слів
- чи згадано в коментарі номер заявки
- чи зміна відбувається у дозволеному часовому вікні
- чи значення полів відповідають шаблону найменування
- чи обов'язкові поля справді заповнені

До нього додаються ще два модулі:

- **Керування оновленнями** — стан оновлень, операційна система, відповідальні та
  історія оновлень для кожної віртуальної машини чи фізичного сервера, за бажанням
  живлені з CheckMK.
- **Graylog** — надсилає події аудиту назовні та повертає відомості з журналів до
  того об'єкта, якому вони належать.

Усе вмикається за бажанням. Після встановлення працює лише перевірка наявності
коментаря з мінімумом у два символи. Решта вмикається у вебінтерфейсі.

## 3. Встановлення

### 3.1 Встановити пакунок

```bash
source /opt/netbox/venv/bin/activate
pip install git+https://github.com/Gasi-Code/netbox-force.git
```

### 3.2 Зареєструвати плагін

У `configuration.py`:

```python
PLUGINS = ['netbox_force']
```

### 3.3 Виконати міграції

```bash
cd /opt/netbox/netbox
python manage.py migrate netbox_force
python manage.py collectstatic --no-input
```

### 3.4 Перезапустити NetBox

```bash
sudo systemctl restart netbox netbox-rq
```

### 3.5 Docker

```bash
docker exec -it <контейнер> pip install git+https://github.com/Gasi-Code/netbox-force.git
docker exec -it <контейнер> /opt/netbox/netbox/manage.py migrate netbox_force
docker restart <контейнер>
```

В образі LinuxServer.io **не** використовуйте для встановлення скрипти
`custom-cont-init.d`. Вони виконуються *після* власних init-скриптів NetBox, що
може призвести до збою міграцій. Docker Mods виконуються перед ними.

Встановлення у файлову систему контейнера не переживе оновлення образу. Додайте
плагін до сталого механізму встановлення плагінів образу, інакше після наступного
pull його не буде.

## 4. Оновлення

```bash
source /opt/netbox/venv/bin/activate
pip install --force-reinstall --no-cache-dir git+https://github.com/Gasi-Code/netbox-force.git
```

`--force-reinstall --no-cache-dir` потрібні тому, що pip кешує за номером версії й
інакше пропустив би перезбирання тієї самої версії.

**Перевірте перед перезапуском.** Цей крок завантажує плагін, не чіпаючи робочий
процес. Якщо він повідомить про помилку, не перезапускайте — робочий NetBox усе ще
тримає старий код у пам'яті й працює далі:

```bash
cd /opt/netbox/netbox
python manage.py check
```

Потім:

```bash
python manage.py migrate netbox_force
python manage.py collectstatic --no-input
sudo systemctl restart netbox netbox-rq
```

### Повернення до попередньої версії

```bash
pip install --force-reinstall --no-cache-dir \
  git+https://github.com/Gasi-Code/netbox-force.git@<commit>
sudo systemctl restart netbox netbox-rq
```

Міграції при цьому зазвичай відкочувати не потрібно. Зайві стовпці не заважають
старому коду — він просто про них не знає. Усе ж зробіть резервну копію бази перед
оновленням.

## 5. Файл конфігурації

`PLUGINS_CONFIG` задає **лише початкові значення**. Після першого запуску кожне
налаштування керується у вебінтерфейсі й зберігається в базі даних.

```python
PLUGINS_CONFIG = {
    'netbox_force': {
        'min_length': 2,
        'exempt_users': ['automation', 'monitoring', 'netbox'],
        'enforce_on_create': False,
        'enforce_on_delete': True,
        'extra_exempt_models': [],
        'checkmk_secret': '',
    },
}
```

| Налаштування | Типово | Значення |
|---|---|---|
| `min_length` | `2` | Мінімум символів у коментарі |
| `exempt_users` | див. вище | Користувачі, звільнені від усіх перевірок, без урахування регістру |
| `enforce_on_create` | `False` | Вимагати коментар і під час створення |
| `enforce_on_delete` | `True` | Вимагати коментар і під час видалення |
| `extra_exempt_models` | `[]` | Додатково звільнені моделі, формат `app.model` |
| `checkmk_secret` | `''` | Необов'язково. Повністю тримає секрет CheckMK поза базою; тоді він має перевагу над полем в інтерфейсі |

## 6. Сторінки

Суперкористувачі знайдуть **NetBox Force** у бічній панелі. Усі сторінки доступні
лише суперкористувачам, якщо не зазначено інше.

| Сторінка | Призначення |
|---|---|
| **Налаштування** | Усі правила примусу, винятки, модулі, webhook, CheckMK |
| **Правила перевірки** | Шаблони імен та обов'язкові поля, за моделлю й полем |
| **Політики моделей** | Відхилення від глобальних налаштувань, за моделлю |
| **Порушення** | Журнал кожної заблокованої зміни з фільтрами, експорт у CSV |
| **Graylog** | Надсилання та читання, див. розділи 7 і 8 |
| **Зведення** | Статистика: які функції ввімкнено, заблоковані зміни, найчастіші користувачі, динаміка за 30 днів |
| **Шаблони імпорту** | Завантажувані CSV-шаблони для масового імпорту NetBox. Видимі всім авторизованим користувачам, коли ввімкнено |
| **Інструкція** | Сторінка з довільним текстом для власних користувачів. Видима всім авторизованим користувачам, коли ввімкнено |
| **Керування оновленнями** | Див. розділ 9 |

Два налаштування заслуговують окремої згадки:

- **Загальний вимикач** — призупиняє всі перевірки, наприклад під час
  обслуговування.
- **Пробний режим (dry-run)** — записує порушення, нічого не блокуючи. Правильний
  спосіб запровадити нове правило: видно, що *було б* заблоковано, перш ніж когось
  справді зупинять.

## 7. Graylog — надсилання

Надсилає події аудиту з NetBox до Graylog через GELF.

### Навіщо

Трьох речей у NetBox більше ніде не записано:

- **Невдалі входи.** NetBox їх узагалі не зберігає.
- **IP-адреса джерела та user agent** зміни. Журнал змін NetBox не несе ані того,
  ані іншого.
- **Зміни налаштувань самого плагіна.** Вони не охоплені журналом змін NetBox — той,
  хто вимикав примус, досі не залишав жодного сліду.

### Налаштування

На сторінці **Graylog**, верхня половина: вузол, порт, транспорт. Потім *Надіслати
тестову подію*.

Почніть із **UDP**. Якщо нічого не надходить, перемкніться на **TCP** — UDP за
своєю природою не може повідомити про збій, TCP може. Це відрізняє «неправильний
порт» від «повідомлення відкинуто».

| Транспорт | Підтверджує доставку | Шифрується |
|---|---|---|
| UDP | ні | ні |
| TCP | так | ні |
| TCP + TLS | так | так |
| HTTP | так | ні |
| HTTPS | так | так |

UDP доречний у локальній мережі й недоречний через інтернет.

### Що надсилається

По рядку на тип події, кожен із прапорцем і рівнем syslog: об'єкт створено,
змінено, видалено; вхід; вихід; невдалий вхід; заблокована зміна; змінено
налаштування плагіна.

### Обсяг

Запит, що змінює більше об'єктів, ніж заданий поріг, повідомляється як **одна
зведена подія**. Імпорт 500 пристроїв — це одна операція; 500 майже однакових
рядків роблять її менш помітною, а не більш.

Зводити, а не обмежувати потік — свідомий вибір. Черга, що спорожнюється повільніше,
ніж наповнюється, відкидає *найновіші* події, тобто саме не ту половину.

### Назви полів

Кожна подія несе ті самі поля, щоб пошук лишався простим:

```
_app          netbox_force
_category     object_change | auth | violation | settings
_event        object_created, login_failed, …
_username
_client_ip
_user_agent
_object_type  dcim.device
_object_id
_object_name
_action       create | update | delete
_changed_fields
_request_id
_netbox_url
_outside_business_hours
```

`_request_id` об'єднує все, що змінив один запит. Сорок пристроїв, відредагованих
разом, — це одна операція, а не сорок загадок.

### Три речі, які варто знати

- **Збій Graylog не може ані сповільнити збереження в NetBox, ані призвести до його
  відмови.** Події потрапляють в обмежену чергу, яку спорожнює фоновий потік. Коли
  черга заповнена, нові події відкидаються й підраховуються, а лічильник видно на
  сторінці.
- **Текст повідомлення завжди англійською**, незалежно від мови інтерфейсу. Запити
  сповіщень у Graylog спираються на цей текст; переклад тихо зламав би кожне
  сповіщення тієї миті, коли хтось змінив би мову.
- **IP клієнта читається з `X-Forwarded-For`**, якщо він присутній. Цей заголовок
  надсилає клієнт, і його можна підробити, якщо NetBox доступний без зворотного
  проксі перед ним.

## 8. Graylog — читання

Приносить відомості з Graylog до NetBox, щоб оцінити вузол, не відкриваючи другу
вкладку.

### Налаштування

Нижня половина сторінки **Graylog**: вебадреса та токен API, потім *Перевірити
з'єднання*. У відповіді зазначено версію Graylog, виявлену форму пошукового API,
найгаласливіші джерела та доступні потоки. *Опитати зараз* виконує опитування
негайно.

**Видайте токен користувачеві Graylog із роллю лише для читання.** Саме це, а не
код цього плагіна, гарантує, що Graylog не можна змінити з NetBox.

### Що тут саме означає «лише читання»

Кожен виклик або отримує дані, або просить Graylog виконати пошук. Стара пошукова
точка входу — звичайний `GET`. Новіший пошуковий API Views — ні: він потребує `POST`
для реєстрації пошуку та ще одного для його виконання. При цьому всередині Graylog
виникає короткочасний об'єкт пошуку й повертаються результати; збережені дані не
змінюються. Якщо у вашому середовищі прийнятний лише `GET`, зафіксуйте форму пошуку
в налаштуваннях на `legacy`.

### Зіставлення джерел з об'єктами NetBox

Точно, у такому порядку, перемагає перший збіг:

| | Правило |
|---|---|
| 1 | **Ручне зіставлення** — щойно задане, завжди має перевагу |
| 2 | **IP-адреса** — джерело проти всіх IP об'єкта |
| 3 | **Ім'я вузла**, без урахування регістру |
| 4 | **Ім'я вузла після відкидання налаштованого доменного суфікса** |

Усе інше лишається незіставленим і так само перелічується.

**Наближеного зіставлення тут навмисно немає.** `srv-web-01` і `srv-web-02`
різняться одним символом, тож будь-яка міра схожості назве їх збігом на 96 %, хоча
це дві різні машини. За нумерованої схеми імен — тобто в будь-якому NetBox, вартому
цієї назви, — найсхожіший кандидат систематично виявляється не тим. Журнали
потрапили б під сусідній сервер, і ніхто б цього не помітив. Схожість
використовується лише для **впорядкування** підказок поруч із незіставленим
джерелом; сама вона нічого не зіставляє.

Якщо перед Graylog стоїть центральний ретранслятор syslog, усі повідомлення несуть
його адресу, і правило 2 не знаходить нічого корисного. Тоді поле джерела має нести
ім'я вузла — саме для цього є правила 3 і 4.

### Сторінки

- **Джерела** — усе, про що звітує Graylog, з лічильниками, з фільтрами за
  зіставленими, незіставленими, мовчазними, ніколи не баченими та ігнорованими.
- **Мовчазні** — зіставлені в NetBox, але більше нічого не надсилають. Вимкнені,
  неправильно налаштовані або залишок із минулого. Жодна із систем не помітить цього
  сама.
- **Ніколи не бачені в Graylog** — друга половина перехресної перевірки.
- **Кластер** — вузли із зеленим/жовтим/червоним індикатором, стан індексатора,
  відставання журналу, кожен вузол пов'язаний зі своєю віртуальною машиною в NetBox.
- **Біля об'єкта** — пристрої та віртуальні машини із зіставленим джерелом
  отримують панель Graylog із лічильниками, останніми повідомленнями на вимогу та
  посиланням у Graylog.

### Навантаження та безпека

- Одне опитування — це **єдиний згрупований запит по всіх вузлах**, а не запит на
  кожен пристрій. Майданчик із 800 пристроями коштує трьох запитів.
- Панель кластера та список повідомлень завантажуються **після** відмальовування
  сторінки. Повільний або мертвий Graylog дає порожню панель, але ніколи —
  підвислу сторінку NetBox.
- Зіставлення живе у власній таблиці плагіна. **Graylog ніколи не пише в основний
  об'єкт NetBox** — видалення плагіна видаляє зіставлення й лишає NetBox недоторканим.
- Точка входу повідомлень відповідає лише для джерела, зіставленого з об'єктом,
  який викликач має право бачити.

## 9. Керування оновленнями та CheckMK

Веде стан оновлень, операційну систему, відповідальних та історію оновлень для
кожної віртуальної машини чи фізичного сервера.

- **Стан** зелений / жовтий / червоний, підтримується вручну або читається з CheckMK.
- **Поріг прострочення** — записи без оновлення протягом N днів позначаються як
  прострочені.
- **Ескалація** — запис, що простояв N днів на *жовтому*, сам стає *червоним*.
- **Контакти** — адміністратор і власник процесу з контактних об'єктів NetBox.
- **Історія оновлень** — по запису на кожен прохід оновлення, з номером заявки та
  приміткою.
- **Доступ** надається за назвою групи NetBox у налаштуваннях плагіна, а не через
  права Django.

### CheckMK

Інтеграція побудована на **pull**: NetBox читає з CheckMK. У CheckMK нічого не
записується, тож достатньо користувача автоматизації лише для читання.

Налаштовується на сторінці налаштувань: URL майданчика, користувач автоматизації,
секрет, фільтр служб та інтервал синхронізації. Секрет зберігається зашифрованим і
більше не показується.

Зупинена синхронізація — це збій, що шкодить найбільше, бо сторінка й далі показує
стан оновлень, який тихо перестав бути правдою. Тому зведення прямо повідомляє, коли
остання успішна синхронізація старша за подвійний інтервал.

## 10. Усунення несправностей

**Плагін не з'являється в бічній панелі.**
Чи задано `PLUGINS` у `configuration.py`? Чи виконано міграції? Чи перезапущено
NetBox? Підписи в бічній панелі оновлюються лише під час перезапуску; вкладки
всередині плагіна — одразу.

**Зміни не блокуються.**
Перевірте в такому порядку: загальний вимикач, пробний режим, чи не входить
користувач до звільнених користувачів або груп, і чи не вимикає політика моделі
примус для цієї моделі.

**Сторінка повідомляє про відсутній стовпець.**
Міграції не виконано або виконано частково.
`python manage.py migrate netbox_force`.

**«Фоновий процес не запущено.»**
`netbox-rq` не працює. Синхронізація CheckMK та опитування Graylog тоді виконуються
лише після натискання кнопки.

**До Graylog нічого не надходить.**
Перемкніть транспорт з UDP на TCP. UDP не може повідомити про збій; TCP може, і його
повідомлення про помилку скаже, чи неправильний порт, чи повідомлення відхилено.

**Панель Graylog біля пристрою лишається порожньою.**
Пристрою не зіставлено джерело. Відкрийте *Джерела → Незіставлені* та зіставте його
або додайте власний доменний суфікс у налаштуваннях, щоб FQDN можна було скоротити.

**Після зміни `SECRET_KEY` секрет CheckMK або токен Graylog перестав працювати.**
Обидва зашифровані ключем, похідним від `SECRET_KEY`. Їх потрібно ввести заново.

## 11. Зміна мови

Мова — це налаштування **на встановлення**, а не на користувача. Змінюється на
сторінці налаштувань.

Вкладки та сторінки всередині плагіна перемикаються одразу. Підписи в бічній панелі
збираються один раз під час запуску й змінюються лише після перезапуску NetBox.

Повідомлення, що показуються користувачам під час блокування, дотримуються цього
налаштування. Повідомлення про помилки API та повідомлення, що надсилаються до
Graylog, лишаються англійськими — див. примітку в
[покажчику документації](../README.md).
