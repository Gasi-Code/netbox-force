## 1. Что делает плагин

NetBox фиксирует, *что* изменилось. NetBox Force решает, *допустимо ли изменение
вообще*, и может заранее потребовать обоснование.

Он стоит между каждой операцией сохранения или удаления и базой данных. Прежде чем
изменение будет записано, он может проверить:

- указан ли комментарий в журнал и достаточно ли он длинный
- не состоит ли комментарий из одних пустых слов
- упомянут ли в комментарии номер заявки
- происходит ли изменение в разрешённом временном окне
- соответствуют ли значения полей шаблону именования
- заполнены ли обязательные поля на самом деле

К нему прилагаются ещё два модуля:

- **Управление обновлениями** — состояние обновлений, операционная система,
  ответственные и история обновлений для каждой виртуальной машины или физического
  сервера, при желании подпитываемые из CheckMK.
- **Graylog** — отправляет события аудита наружу и приносит сведения из журналов
  обратно, к тому объекту, которому они принадлежат.

Всё включается по желанию. После установки работает только проверка наличия
комментария, с минимумом в два символа. Остальное включается в веб-интерфейсе.

## 2. Требования

| Составляющая | Версия | Примечание |
|---|---|---|
| NetBox | 4.0.0 или новее | |
| Python | 3.10 или новее | |
| PostgreSQL | — | Требуется самим NetBox |
| `cryptography` | любая | Поставляется с NetBox. Без неё секрет CheckMK и токен Graylog хранятся незашифрованными, и плагин сообщает об этом на странице настроек |
| `requests` | любая | Поставляется с NetBox. Нужна для CheckMK и Graylog |
| Процесс RQ | — | Только для запланированной синхронизации CheckMK и опроса Graylog. Без него обе работают по требованию, и страница об этом сообщает |

## 3. Установка

### 3.1 Установить пакет

```bash
source /opt/netbox/venv/bin/activate
pip install git+https://github.com/Gasi-Code/netbox-force.git
```

### 3.2 Зарегистрировать плагин

В `configuration.py`:

```python
PLUGINS = ['netbox_force']
```

### 3.3 Выполнить миграции

```bash
cd /opt/netbox/netbox
python manage.py migrate netbox_force
python manage.py collectstatic --no-input
```

### 3.4 Перезапустить NetBox

```bash
sudo systemctl restart netbox netbox-rq
```

### 3.5 Docker

```bash
docker exec -it <контейнер> pip install git+https://github.com/Gasi-Code/netbox-force.git
docker exec -it <контейнер> /opt/netbox/netbox/manage.py migrate netbox_force
docker restart <контейнер>
```

В образе LinuxServer.io **не** используйте для установки скрипты
`custom-cont-init.d`. Они выполняются *после* собственных init-скриптов NetBox, что
может привести к сбою миграций. Docker Mods выполняются до них.

Установка внутрь файловой системы контейнера не переживёт обновления образа.
Добавьте плагин в постоянный механизм установки плагинов образа, иначе после
следующего pull его не будет.

## 4. Обновление

```bash
source /opt/netbox/venv/bin/activate
pip install --force-reinstall --no-cache-dir git+https://github.com/Gasi-Code/netbox-force.git
```

`--force-reinstall --no-cache-dir` нужны потому, что pip кэширует по номеру версии
и иначе пропустил бы пересборку той же версии.

**Проверьте перед перезапуском.** Этот шаг загружает плагин, не трогая работающий
процесс. Если он сообщит об ошибке, не перезапускайте — работающий NetBox всё ещё
держит старый код в памяти и продолжает работать:

```bash
cd /opt/netbox/netbox
python manage.py check
```

Затем:

```bash
python manage.py migrate netbox_force
python manage.py collectstatic --no-input
sudo systemctl restart netbox netbox-rq
```

### Возврат к прежней версии

```bash
pip install --force-reinstall --no-cache-dir \
  git+https://github.com/Gasi-Code/netbox-force.git@<commit>
sudo systemctl restart netbox netbox-rq
```

Миграции при этом обычно откатывать не нужно. Лишние столбцы не мешают старому
коду — он просто о них не знает. Всё же сделайте резервную копию базы перед
обновлением.

## 5. Файл конфигурации

`PLUGINS_CONFIG` задаёт **только начальные значения**. После первого запуска каждая
настройка управляется в веб-интерфейсе и хранится в базе данных.

```python
PLUGINS_CONFIG = {
    'netbox_force': {
        'min_length': 2,
        'exempt_users': ['automation', 'monitoring', 'netbox'],
        'enforce_on_create': False,
        'enforce_on_delete': True,
        'extra_exempt_models': [],
        'checkmk_secret': '',
    },
}
```

| Настройка | По умолчанию | Значение |
|---|---|---|
| `min_length` | `2` | Минимум символов в комментарии |
| `exempt_users` | см. выше | Пользователи, освобождённые от всех проверок, без учёта регистра |
| `enforce_on_create` | `False` | Требовать комментарий и при создании |
| `enforce_on_delete` | `True` | Требовать комментарий и при удалении |
| `extra_exempt_models` | `[]` | Дополнительно освобождённые модели, формат `app.model` |
| `checkmk_secret` | `''` | Необязательно. Полностью удерживает секрет CheckMK вне базы; тогда он имеет приоритет над полем в интерфейсе |

## 6. Страницы

Суперпользователи найдут **NetBox Force** в боковой панели. Все страницы доступны
только суперпользователям, если не указано иное.

| Страница | Назначение |
|---|---|
| **Настройки** | Все правила принуждения, исключения, модули, webhook, CheckMK |
| **Правила проверки** | Шаблоны имён и обязательные поля, по модели и полю |
| **Политики моделей** | Отступления от глобальных настроек, по модели |
| **Нарушения** | Фильтруемый журнал каждого заблокированного изменения, выгрузка в CSV |
| **Graylog** | Отправка и чтение, см. разделы 7 и 8 |
| **Сводка** | Статистика: какие функции включены, заблокированные изменения, самые частые пользователи, динамика за 30 дней |
| **Шаблоны импорта** | Загружаемые CSV-шаблоны для массового импорта NetBox. Видны всем вошедшим пользователям, если включены |
| **Инструкция** | Страница свободного текста для собственных пользователей. Видна всем вошедшим пользователям, если включена |
| **Управление обновлениями** | См. раздел 9 |

Две настройки заслуживают отдельного упоминания:

- **Общий выключатель** — приостанавливает все проверки, например на время
  обслуживания.
- **Пробный режим (dry-run)** — записывает нарушения, ничего не блокируя. Правильный
  способ вводить новое правило: видно, что *было бы* заблокировано, прежде чем
  кого-то действительно остановят.

## 7. Graylog — отправка

Отправляет события аудита из NetBox в Graylog по GELF.

### Зачем

Три вещи не записываются в NetBox больше нигде:

- **Неудачные входы.** NetBox их вообще не хранит.
- **IP-адрес источника и user agent** изменения. Журнал изменений NetBox не несёт
  ни того, ни другого.
- **Изменения настроек самого плагина.** Они не охвачены журналом изменений NetBox —
  тот, кто отключал принуждение, до сих пор не оставлял никакого следа.

### Настройка

На странице **Graylog**, верхняя половина: узел, порт, транспорт. Затем *Отправить
тестовое событие*.

Начните с **UDP**. Если ничего не приходит, переключитесь на **TCP** — UDP по своей
природе не может сообщить об ошибке, TCP может. Это отличает «неверный порт» от
«сообщение отброшено».

| Транспорт | Подтверждает доставку | Шифруется |
|---|---|---|
| UDP | нет | нет |
| TCP | да | нет |
| TCP + TLS | да | да |
| HTTP | да | нет |
| HTTPS | да | да |

UDP уместен внутри локальной сети и неуместен через интернет.

### Что отправляется

По строке на тип события, каждая с флажком и уровнем syslog: объект создан,
изменён, удалён; вход; выход; неудачный вход; заблокированное изменение; изменены
настройки плагина.

### Объём

Запрос, изменяющий больше объектов, чем заданный порог, сообщается как **одно
сводное событие**. Импорт 500 устройств — это одна операция; 500 почти одинаковых
строк делают её менее заметной, а не более.

Сводить, а не ограничивать поток — сознательный выбор. Очередь, которая
опустошается медленнее, чем наполняется, отбрасывает *самые новые* события, то есть
именно не ту половину.

### Имена полей

Каждое событие несёт одни и те же поля, чтобы поиск оставался простым:

```
_app          netbox_force
_category     object_change | auth | violation | settings
_event        object_created, login_failed, …
_username
_client_ip
_user_agent
_object_type  dcim.device
_object_id
_object_name
_action       create | update | delete
_changed_fields
_request_id
_netbox_url
_outside_business_hours
```

`_request_id` объединяет всё, что изменил один запрос. Сорок устройств,
отредактированных разом, — это одна операция, а не сорок загадок.

### Три вещи, которые стоит знать

- **Сбой Graylog не может ни замедлить сохранение в NetBox, ни привести к его
  отказу.** События попадают в ограниченную очередь, которую опустошает фоновый
  поток. Когда очередь заполнена, новые события отбрасываются и подсчитываются, а
  счётчик виден на странице.
- **Текст сообщения всегда на английском**, независимо от языка интерфейса. Запросы
  оповещений в Graylog опираются на этот текст; перевод молча сломал бы каждое
  оповещение в тот момент, когда кто-нибудь сменил бы язык.
- **IP клиента читается из `X-Forwarded-For`**, если он присутствует. Этот заголовок
  присылает клиент, и его можно подделать, если NetBox доступен без обратного прокси
  перед ним.

## 8. Graylog — чтение

Приносит сведения из Graylog в NetBox, чтобы оценить узел, не открывая вторую
вкладку.

### Настройка

Нижняя половина страницы **Graylog**: веб-адрес и токен API, затем *Проверить
подключение*. В ответе указываются версия Graylog, обнаруженная форма поискового
API, самые шумные источники и доступные потоки. *Опросить сейчас* выполняет опрос
немедленно.

**Выдайте токен пользователю Graylog с ролью только для чтения.** Именно это, а не
код плагина, гарантирует, что Graylog нельзя изменить из NetBox.

### Что здесь точно означает «только чтение»

Каждый вызов либо получает данные, либо просит Graylog выполнить поиск. Старая
поисковая точка входа — обычный `GET`. Более новый поисковый API Views — нет: он
требует `POST` для регистрации поиска и ещё одного для его выполнения. При этом
внутри Graylog возникает недолговечный объект поиска и возвращаются результаты;
сохранённые данные не меняются. Если в вашей среде приемлем только `GET`, зафиксируйте
форму поиска в настройках на `legacy`.

### Сопоставление источников с объектами NetBox

Точно, в этом порядке, побеждает первое совпадение:

| | Правило |
|---|---|
| 1 | **Ручное сопоставление** — однажды заданное, всегда имеет приоритет |
| 2 | **IP-адрес** — источник против всех IP объекта |
| 3 | **Имя узла**, без учёта регистра |
| 4 | **Имя узла после отбрасывания заданного доменного суффикса** |

Всё остальное остаётся несопоставленным и так и перечисляется.

**Приблизительного сопоставления здесь намеренно нет.** `srv-web-01` и `srv-web-02`
различаются одним символом, поэтому любая мера схожести назовёт их совпадающими на
96 %, хотя это две разные машины. При нумерованной схеме имён — то есть в любом
NetBox, достойном этого названия, — самый похожий кандидат систематически оказывается
не тем. Журналы попали бы под соседний сервер, и никто бы этого не заметил. Схожесть
используется исключительно для **упорядочивания** подсказок рядом с несопоставленным
источником; сама она ничего не сопоставляет.

Если перед Graylog стоит центральный ретранслятор syslog, все сообщения несут его
адрес, и правило 2 не находит ничего полезного. Тогда поле источника должно нести
имя узла — для этого и существуют правила 3 и 4.

### Страницы

- **Источники** — всё, о чём сообщает Graylog, со счётчиками, с фильтрами по
  сопоставленным, несопоставленным, молчащим, ни разу не замеченным и игнорируемым.
- **Молчащие** — сопоставлены в NetBox, но больше ничего не присылают. Мертвы,
  неверно настроены или остаток от прошлого. Ни одна из систем не заметит этого сама.
- **Ни разу не замечены в Graylog** — вторая половина перекрёстной проверки.
- **Кластер** — узлы с зелёным/жёлтым/красным индикатором, состояние индексатора,
  отставание журнала, каждый узел связан со своей виртуальной машиной в NetBox.
- **У объекта** — устройства и виртуальные машины с сопоставленным источником
  получают панель Graylog со счётчиками, последними сообщениями по запросу и ссылкой
  в Graylog.

### Нагрузка и безопасность

- Один опрос — это **единственный сгруппированный запрос по всем узлам**, а не
  запрос на каждое устройство. Площадка с 800 устройствами стоит трёх запросов.
- Панель кластера и список сообщений загружаются **после** отрисовки страницы.
  Медленный или мёртвый Graylog даёт пустую панель, но никогда — зависшую страницу
  NetBox.
- Сопоставление живёт в собственной таблице плагина. **Graylog никогда не пишет в
  основной объект NetBox** — удаление плагина удаляет сопоставление и оставляет
  NetBox нетронутым.
- Точка входа сообщений отвечает только для источника, сопоставленного с объектом,
  который вызывающий вправе видеть.

## 9. Управление обновлениями и CheckMK

Ведёт состояние обновлений, операционную систему, ответственных и историю
обновлений для каждой виртуальной машины или физического сервера.

- **Состояние** зелёное / жёлтое / красное, поддерживается вручную либо читается из
  CheckMK.
- **Порог просрочки** — записи без обновления в течение N дней помечаются как
  просроченные.
- **Эскалация** — запись, простоявшая N дней на *жёлтом*, сама становится *красной*.
- **Контакты** — администратор и владелец процесса из контактных объектов NetBox.
- **История обновлений** — по записи на каждый проход обновления, с номером заявки
  и примечанием.
- **Доступ** выдаётся по имени группы NetBox в настройках плагина, а не через права
  Django.

### CheckMK

Интеграция построена на **pull**: NetBox читает из CheckMK. В CheckMK ничего не
записывается, поэтому достаточно пользователя автоматизации только для чтения.

Настраивается на странице настроек: URL площадки, пользователь автоматизации,
секрет, фильтр служб и интервал синхронизации. Секрет хранится в зашифрованном виде
и больше не показывается.

Остановившаяся синхронизация — это сбой, который причиняет больше всего вреда,
потому что страница продолжает показывать состояние обновлений, которое молча
перестало быть правдой. Поэтому сводка прямо сообщает, когда последняя успешная
синхронизация старше двойного интервала.

## 10. Устранение неполадок

**Плагин не появляется в боковой панели.**
Задан ли `PLUGINS` в `configuration.py`? Выполнены ли миграции? Перезапущен ли
NetBox? Подписи в боковой панели обновляются только при перезапуске; вкладки внутри
плагина — сразу.

**Изменения не блокируются.**
Проверьте в таком порядке: общий выключатель, пробный режим, не входит ли
пользователь в освобождённых пользователей или группы, и не отключает ли политика
модели принуждение для этой модели.

**Страница сообщает об отсутствующем столбце.**
Миграции не выполнены или выполнены частично.
`python manage.py migrate netbox_force`.

**«Фоновый процесс не запущен.»**
`netbox-rq` не работает. Синхронизация CheckMK и опрос Graylog тогда выполняются
только по нажатию кнопки.

**В Graylog ничего не приходит.**
Переключите транспорт с UDP на TCP. UDP не может сообщить об ошибке, TCP может, и
его сообщение об ошибке скажет, неверен ли порт или сообщение было отклонено.

**Панель Graylog у устройства остаётся пустой.**
Устройству не сопоставлен источник. Откройте *Источники → Не сопоставленные* и
сопоставьте его либо добавьте свой доменный суффикс в настройках, чтобы FQDN можно
было сократить.

**После смены `SECRET_KEY` секрет CheckMK или токен Graylog перестал работать.**
Оба зашифрованы ключом, производным от `SECRET_KEY`. Их нужно ввести заново.

## 11. Смена языка

Язык — настройка **на установку**, а не на пользователя. Меняется на странице
настроек.

Вкладки и страницы внутри плагина переключаются сразу. Подписи в боковой панели
собираются один раз при запуске и меняются только после перезапуска NetBox.

Сообщения, показываемые пользователям при блокировке, следуют этой настройке.
Сообщения об ошибках API и сообщения, отправляемые в Graylog, остаются английскими —
см. примечание в [указателе документации](../README.md).
